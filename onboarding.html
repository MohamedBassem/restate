What is Restate?

Restate is a distributed runtime that gives applications durable execution, durable promises/timers, exactly-once communication, and consistent K/V state per entity. The user-facing pitch and primitives live in README.md:7–104.

Workspace version at time of writing: 1.7.0-dev, Rust edition 2024, MSRV 1.95.0 Cargo.toml:35–38. License is BUSL-1.1 Cargo.toml:39.

Key runtime crates

The runtime is decomposed into many crates. The ones you will touch most as a new runtime engineer:

restate-core

Task center, metadata, network, partitions infra. Entry: crates/core/src/lib.rs:19–27.

restate-bifrost

Distributed log abstraction (Bifrost, Appender, LogReadStream, loglet providers). Re-exports at crates/bifrost/src/lib.rs:28–37.

restate-worker

Hosts partition processors and invoker integration. See crates/worker/src/partition_processor_manager.rs and crates/worker/src/partition/.

restate-invoker-impl

Drives invocations against SDK deployments. Crate at crates/invoker-impl/.

restate-partition-store

RocksDB-backed per-partition storage.

restate-log-server

Replicated loglet storage server (plus restate-log-server-grpc).

restate-metadata-server / store / providers

Cluster metadata plane.

restate-ingress-http / ingress-kafka

External request entry points into the cluster.

restate-admin / admin-rest-model

Admin API server and shared REST models.

restate-node

Composes a Restate node from the components above.

restate-types

Core domain types shared across crates (IDs, partitions, journal, logs, schema). Entry at crates/types/src/lib.rs.

restate-storage-query-datafusion

CLAUDE.md (Rust Code Style Guide §1)

Hard rules

  • Never hold a reference from Configuration::pinned() across an .await. CLAUDE.md §4
  • Prefer restate_clock::WallClock over std::time::SystemTime. CLAUDE.md §8
  • Use ByteCount::from(value) from restate_memory for byte sizes in logs/errors. CLAUDE.md (style guide)
  • Use KeyRange (from restate_sharding, re-exported as restate_types::sharding::KeyRange) instead of RangeInclusive<PartitionKey> — it is Copy, 16 bytes vs 24, and wire-compatible serde/bilrost. CLAUDE.md (style guide)
  • New or deprecated config options must carry /// Since vX.Y.Z in their doc comment. CLAUDE.md (style guide)
  • Make illegal states unrepresentable; lean on niches (Option<NonZeroU32>, etc.). CLAUDE.md §6–7
  • Crate names: hyphenated and prefixed restate-, placed under crates/ without the prefix. docs/dev/rust-guidelines.md:16–17
  • Avoid Box<dyn Error>; use anyhow::Error only when the consumer doesn’t need to distinguish variants. Otherwise prefer thiserror + CodedError. docs/dev/rust-guidelines.md:81–84

Tests

Keep unit-test maintenance in check: prefer high-signal tests on important paths; pack multiple assertions per test rather than splitting into many functions. CLAUDE.md (style guide)

Component design pattern

Every Restate component tends to follow the same shape — internalize this; you will see it everywhere:

  • Options: serde::{Serialize,Deserialize} + schemars::JsonSchema; has a build() that returns the Service.
  • Service: owns the event loop. run(self, ..., drain: drain::Watch) listens for shutdown.
  • Handle: cheap-to-clone interface to the service; usually wraps a channel under the hood. Obtained via Service::handle(&self).
  • Error: thiserror-based, often annotated with CodedError.
  • When possible, split a component into _api (handle + error types) and _impl (the service).

Event-loop discipline: don’t pass channels in — let the service create them and hand out handles. docs/dev/rust-guidelines.md:36–70

Ordering caveat: ordering is only preserved on a single channel. Two channels between the same pair of components is a race condition magnet. docs/dev/rust-guidelines.md:72–77

Pre-commit validation

Before committing, run (the order matters for fast feedback):

cargo check
cargo nextest run --all-features
cargo fmt --all -- --check
cargo clippy --all-features --all-targets --workspace -- -D warnings

# Only if you touched Cargo.toml / Cargo.lock:
cargo deny --all-features check
cargo hakari generate    # regenerate workspace-hack

CLAUDE.md (Validation Before Committing Changes)

Latency-critical paths handle with care

Performance is a first-class concern (after correctness). Be especially careful when changing these areas — avoid needless allocations and prefer references:

  • Bifrost — crates/bifrost/
  • Networking layer — crates/core/src/network/
  • restate-core — task center, metadata, partitions infra
  • Partition processor state machine — crates/worker/src/partition/
  • Invoker — crates/invoker-impl/

Suggested first week

  1. Mon: Install toolchain (Rust, clang, cmake, protoc, just). Run just build --bin restate-server and just test end-to-end.
  2. Tue: Read docs/dev/development-guidelines.md, docs/dev/rust-guidelines.md, docs/dev/debug.md, and CLAUDE.md cover-to-cover.
  3. Wed: Trace one invocation end-to-end: ingress-http → worker partition processor → invoker-impl → bifrost log writes. Start with the entry crates listed above.
  4. Thu: Skim restate-core task center and restate-bifrost public API (Bifrost, Appender, LogReadStream). Trace how a record flows from producer to a partition processor.
  5. Fri: Pick a "good first issue" or a small cleanup in a hot-path crate; submit a PR following the component pattern, validation steps, and release-notes rule.
